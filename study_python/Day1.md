## 데이터베이스

- 페이지데이터베이스: 사이드바에서 새로 생성하는 방식 페이지 하나가 데이터베이스 전체가 됨. 최상위 폴더에 있으면 다른 파일들에서도 사용가능
- 인라인데이터베이스: 기존 페이지 안에 표를 삽입하는 방식 데이터베이스가 들어있는 파일에서만 사용가능

1. 이름속성
2. 텍스트 속성: 요약, 설명
3. 숫자 속성: 숫자의 단위, 형식, 표시, 옵션(점수, 금액, 비율 등)
4. 선택 속성: 하나의 옵션만을 선택 할 때 사용(우선순위, 카테고리)
5. 다중 선택 속성: 여러 옵션을 동시에 선택(관련태그, 기술 스택, 학습 분야 등)
6. 상태 속성: 단계별 진행 상황을 표시 할 수 있는 선택 속성(진행 상태 등)
7. 날짜 속성:날짜와 시간을 표시 할 수 있을 뿐더러 종료일 설정 및 리마인더 알림 설정 가능
8. 사람 속성: 노션사용자 계정을 지정해 표시 가능 (주로 협업 할 때 사용)
9. 파일과 미디어 속성: 문서, 이미지, 동영상 등 다양한 자료 첨부가능
10. 체크박스 속성: 할일 목록 블록과 같은 개념 완료 여부 표시할때 유용
11. URL속성: 외부 링크를 기록 할 수 있음(링크 주소)
12. 수식속성: 위의 속성 값 또는 값들의 조합으로 새로운 속성 만들기 가능(외우기보다AI맡기는게 효율적 )

## 명령어

- pwd: 현재 위치
- mkdir: 폴더 생성 ex)mkdir my_story -> 현재 위치에 my_story폴더 생성
- ls: 일반 파일 및 폴더 목록
- ls -a: 숨김파일 포함 전체목록
- ls -l: 파일 및 폴더 상세정보
- ls -al: 숨김파일 포함 상세정보



- touch: 빈파일 생성 ex) touch story.txt ->story.txt 파일 생성
- cat: 파일 내용 확인 ex) cat story.txt -> 파일내용이 보임



##### 깃허브 연동

- git config --global user.name "사용자이름"
- git config --global user.email "사용자주소"

> 위의 두가지는 오타가 나도 오류가 나지않아 확인필요

- git config --global --list(확인하기)



- git init (GIT 저장소 초기화, 현재 폴더에서 Git으로 버전 관리를 시작하기 위한 명령어)
- git status (Git 저장소의 상태를 확인)
- git add .(변경 사항 전부 스테이징, 필요한 것만 스테이징 하려면 .뒤에 파일이름)
- git commit -m (이미 스테이징 되어있는 파일만 커밋, 현재 위치한 브랜치에 커밋) ex) git commit -m "첫번째수정" ->"첫번째수정" 으로 커밋됨
- git commit -am(기존 추적되고 있는 파일만 스테이징+커밋, 위와동일, 만약 추적되고 있지 않은 파일을 커밋해야 한다면 git add .후 사용)



- git log(커밋 기록보기)
- git log --oneline(커밋 기록 요약보기)
- git log --oneline --파일이름(특정 파일만 커밋 기록 요약보기)
- git diff(변경사항 보기)



- git rm test.txt -> test.txt를 git에서 제거하고 실제 파일도 삭제
- git rm --cached test.txt -> test.txt를 git에서만 제거하고 실제 파일은 유지
- git restore --staged tset.txt -> 스테이징만 취소 (추적은 되고있던 것이라서 git commit -am 가능)



- git switch main/dev (해당 브랜치로 이동)
- git push -u origin main/dev (깃허브의 main이나 dev 브랜치에 업로드)



- git reset --soft 커밋ID (커밋만 취소하고 스테이징 상태와 파일 유지, 보통 다른 파일을 추가해서 커밋하려고 할때 사용됨 )
- git reset 커밋ID (--mixed이지만 reset만 써도 기본값이 --mixed, 커밋 취소+스테이징취소, 보통 스테이징한 변경사항을 이번 커밋에서 제외하거나 스테이징한 파일을 수정할때 사용함)

> 위의 두개의 리셋은 파일 변경사항이 남아있음

- git reset --hard 커밋ID (파일 변경 사항이 전혀 남아있지 않음 사용시 주의)

> - git reset 3종류는 현재 작업중인 브랜치에 적용되는 것이라 뒤에 main, dev를 안붙힘
> - git reset --hard main (dev브랜치에서 해당 명령어 사용시 dev 브랜치를 main이 가르키는 커밋으로 이동시킴)
>
> main: a-b-c
> dev: a-b-d-e 일 경우 위의 명령어 사용시 d, e삭제 dev: a-b-c

- echo "블라블라블라" >> README.md (README.md에 블라블라블라를 뒤에 추가함 만약 README.md가 없다면 생성후 추가)
- echo "블라블라블라" > README.md (README.md 파일이 없다면 생성후 추가는 맞지만 원래 README.md가 있다면 이전 내용에 덮어씌우는 거라 기존글이 사라지고 블라블라블라를 덮어씌움 )
